# 10分钟极速复现指南（评委用）

目标：在已安装 Android Studio / SDK 的前提下，约 10 分钟从空环境跑到可演示的「中央学生助手」主线，并在过程页点开留痕。首次安装 SDK 或创建模拟器不计入这 10 分钟。

仓库：[MIMIMIXIAOBAI/Student-Spending-Bill](https://github.com/MIMIMIXIAOBAI/Student-Spending-Bill)（须保持 Public 或向评委开放访问）  
包名：`com.campusbill.app` · 纯 Java + Room · 本地路径约定：`E:\AI\Student Spending Bill`

交赛材料总清单见 [SUBMISSION-CHECKLIST.md](SUBMISSION-CHECKLIST.md)。环境变量模板见 [env.example](env.example)。

## 1. 环境配置

| 项 | 要求 |
|---|---|
| Android Studio | Narwhal 或更新（内含 JDK 17） |
| SDK | Platform API 37 + Build-Tools；模拟器建议 API 29+、Graphics = Hardware |
| Gradle | 使用仓库自带 Wrapper（无需单独安装） |
| 本机文件 | 根目录创建 `local.properties`，写入 `sdk.dir=...`（该文件已 gitignore） |

```powershell
git clone https://github.com/MIMIMIXIAOBAI/Student-Spending-Bill.git
cd "Student-Spending-Bill"
# 按 docs/assistant/env.example 写入 local.properties 后：
.\gradlew.bat assembleDebug installDebug
```

或用 Android Studio 打开仓库根目录，Sync 后 Run。不要把 DeepSeek Key 写进任何仓库文件或 `gradle.properties`。

## 4. 首次启动：DeepSeek Key 向导

1. 打开应用，在记账首页「智能消费账单助手」下方找到常驻大球（已替换原「AI消费建议」卡片；白卡左右各留 16dp，高度约 260dp、上限 300dp）。位移不超过 12dp 的轻点进入中央助手对话页（现有 `AiChatActivity` 扩展，仍为竖屏）；上下滑动不要判成进入。
2. 按向导粘贴 **DeepSeek API Key**。密钥写入本机 Keystore，仅本机有效。
3. 向导应给出「测通 / 失败」结果后再进入对话。失败时文字状态为「出错」（密钥失败、余额不足、网络错误），检查网络与 Key，不要改仓库配置。

默认接口与模型以向导内预填为准（账本阶段曾默认 `https://api.deepseek.com/chat/completions`、`deepseek-chat`，以当前向导文案为准）。

## 5. 演示主线（请按顺序说）

建议先确保本机 Room 里已有本周食堂相关账单，并最好另有若干历史导入或更早手记的记录（可用「记一笔」或导入；评测机可用仓库 `模拟账单/`）。本周按周一至周日，日期 `YYYY-MM-DD`。用户问「当月」时，按首页折线图当前选中的年月查询，不要用切换前的数据。

涉及账单或消费的问题，必须先查本机 Room 里的真实账单再回答。金额、笔数、商户和分类只能来自本轮只读工具 `query_spend` 的结果，不能口算或编。查账范围包括用户历史导入和手动记下的全部记录，和记账页是同一本账。用户指定了时间就按现有区间查；没指定、或问历史/整体习惯/消费建议时，用新的 `period=all` 查全部记录，合计和分类汇总要完整，明细过多可以截断。应用侧也要卡住：这类问题若本轮还没成功查到账，就不要把带数字的回复直接给用户。过程只走「调用工具」和表情 `32`（查账也可用 `40`），不弹确认卡，不新增工具，不改四档状态。查不到对应账单时，直接在回复里说明没有匹配数据。

文字状态共四档，独立可见：**思考 / 调用工具 / 等待确认 / 出错**。确认卡只出现在「等待确认」。回复为流式字符输出（硬指标）；思考过程可可视化。Emotion Ball 不能替代文字状态。不新增第五文字状态。

记账首页「智能消费账单助手」下用常驻大球替换「AI消费建议」卡片（白卡左右 16dp，高度约 260dp、上限 300dp），卡上滑动时视线跟随，位移不超过 12dp 的轻点进入对话页，不要把上下滑判成进入。首页大球与对话页的球均可用手机姿态（旋转向量/陀螺仪）驱动视线，调用 `setGaze` 看向倾斜方向：只在空闲 `02`、且页面可见时生效；进后台或离开当前页就停，继续 `setActive(false)`。球在思考 `30`、流式出字 `39`、调用工具 `32`/`40`、等待确认 `03`、出错 `34`、成功 `33` 和报数 `19`（含回 `02` 前的 1.5 秒）时不激活，表情一开始就把视线约 400ms 收回中心。相对握持姿态偏转不足 8° 当作微抖，不驱动；达到 12° 后用 `setGaze` 看向倾斜方向，约 30° 看满（±1），回落到 8° 以内再经 400ms 回正（与手指滑动松开一致）。手指正在滑动跟随时触摸优先；幅度不够时仍按现有点击/滑动跟随。不新增加表情，不另开设置开关。对话页留下球面板，默认高度约占屏幕的三分之一，把下部留给对话，不要再做大面板；不要改回顶栏小圆球。对话页球容器全透明，去掉白底、描边和方形阴影，只留球体；旁边空白要能点到消息、也能继续滑。历史上滑时列表伸到顶栏下方、从球后面过去，不要被方框硬切。渐隐高度 48dp 作废，不定死一个 dp，也不拉到球中部。渐隐从球体下沿拉到球体上沿，按当前球高全宽线性：下沿完全透明，上沿用对话页现有页底浅灰到完全不透明；从球体上沿到顶栏保持同一浅灰，不要再留一段全透明，避免割裂。不要另起颜色，也不要横档。球体本身仍不透明、字不透过球；两侧仍可点可滑，靠近球体下沿仍可透出文字，只是视觉上不再在渐隐上方突然露字。压到 160dp 时，渐隐仍贴着球体下沿、铺满当时的球高，上沿仍接到区域顶。只改对话页，首页大球仍用原来的白卡。键盘或确认卡出现时压到 160dp，这是硬下限，不要再往下压。若压到 160dp 仍可能挡住，优先露出输入栏、状态行、确认卡和流式回复，球停在 160dp，由消息区让位，而不是继续缩小球。打字弹出键盘时，输入栏和正在输入的内容必须完整留在键盘上方，对话列表上收，状态行钉在输入栏上方，确认卡也不能被盖住；窗口用 `adjustResize`，不要让键盘直接叠在输入框上。表情必须用 Emotion Ball 官方两位 `emotionId` 调用 `setEmotion('35')` 这类字符串，不要再用 `listening` / `pleased` 等自造名；未知 ID 会回退到 `02` 待机放空。只使用已有 32 个编号（`00`–`07`、`10`–`21`、`30`–`41`），完整陈列见 [Emotion Ball 表情馆](https://sam70361.github.io/aora-bot/)。对照：空闲 `02` 待机放空；思考 `30` 思考中（并走现有「思考」状态）；流式出字 `39` 输出回复；回复结束（成功/激动）`33` 任务完成，约 1.5 秒后回 `02`；查询报出数字用更克制的 `19` 满意，1.5 秒后回 `02`；调用工具 `32` 处理中忙碌，查账单也可用 `40` 检索资料；等待确认 `03` 好奇；出错 `34` 出错；用户取消确认回 `02`，不要用失落。倾听表情 `35` 不再用于已取消的语音输入，不要再按按住说话去切这个表情。

**语音输入已取消（真机效果记为未通过）。** 输入栏只保留输入框和发送键，不留麦克风空槽；红色麦克风、按住预览、松开发送、系统识别和 Vosk 离线回退都不是当前产品能力。底部不再留麦克风占位，也不要垫成大块空白。输入栏整行 56dp（上下各 8dp、输入框 40dp，左右 16dp）。字多了最多长到 96dp（约 3 行）再在框里滚，不要一开始就按多行占高。状态行只在有「思考 / 调用工具 / 等待确认 / 出错」时出现，高 32dp，空闲时不占位。右下角「上下文 xx%」是 12sp 一行、上下各 4dp，不做卡片。没有消息时，消息区不放占位白卡、不垂直居中，顶距 8dp，腾出的高度给对话列表。本演示主线只用文字输入。
