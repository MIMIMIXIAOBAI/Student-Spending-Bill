# 会话与上下文协议 v0.1（已冻，2026-11-10）

本包只做对话历史；语音输入已取消，不再改 `测试v0.8.1` 的语音。球、陀螺仪、月份同步等暂缓项本包不动。不另开独立 App，仍在现有对话页上做。版式参考 DeepSeek 网页结构，但按现在的手机端风格，不要整页仿桌面站。

## 会话持久

- 会话和消息都存在本地 Room。当前会话 id 要写盘。切页、切到底栏、退到后台或关掉再进，都恢复同一条会话、完整上下文和滚动位置，不要自动新开。不上传、不另做同步，不把密钥写入会话记录。
- 只有用户点「新建对话」时，才手动新开一个会话。快用满时的自动开下一轮见下节，不在此列。
- 历史列表按最近更新排列；标题用该会话首条用户消息。允许重命名和删除：长按列表项出现「重命名」「删除」。重命名用一张小的 Grouped 输入框，取消 / 保存，空标题回退为首条用户消息。左滑删除和确认框保留。先不做文件夹、搜索、置顶。
- 旧会话完整留在列表里，可再打开。

## 侧栏（按 UI 规格）

对话页不要常驻左侧栏，以免和约占屏高三分之一的球、消息区抢位置。改为从左缘滑入，或点顶栏左侧入口打开抽屉：宽约屏幕 80%、最大 320dp，220ms 左滑入；浅灰底、白卡分组、几乎无描边。抽屉顶部是「新建对话」，下面是历史列表（新的在上，当前项高亮），点一行切换。

## 上下文占用

- 在消息区右下角、状态行和输入栏之上，用一行次要灰字显示，例如「上下文 62%」。这不是状态行，也不是卡片，不新增第五档文字状态，不让模型输出该字段。
- 百分比按「当前请求实际占用的上下文 token / 当前模型窗口」计算，不要用消息条数估算。窗口值以当前所用 DeepSeek 模型为准。
- 约 80% 起改为提示色，约 95% 起加重。

## 快用完时的要点交接

不要再用「到 80% 就自动开新场」，也不要在 80% 预存时再走一轮「思考」。

到达约 80%，且本轮回复结束后：只在后台预存要点，不切换会话、不弹确认、也不再走一轮「思考」，避免回复已经结束又出现思考态。当前对话继续。抽出需要长期记住的要点（消费习惯、已确认账单、偏好与仍有效的约束等，不是整段原文）。不新增工具。旧会话完整留在列表里可再打开。

- 用户点「新建对话」时，若已有预存，则带入新对话；顶部仍是一条可点掉的 Grouped 提示「已带入上次的关键记忆」，球为 `02` 待机放空。
- 只有约 95%，或发送前判断本轮请求会超窗，才自动开下一场并带入记忆，避免卡死。
- 若当时还没预存成功，再走「思考」和表情 `30` 抽完后切换。
- 失败则留在当前会话，状态「出错」，右侧「重试」，球为 `34`。
- 新会话只注入这份压缩要点，不要把全部旧消息再塞一遍。
- 若应用注入了「上一会话要点」，模型只使用其中已写出的事实，不得假装记得未写入的内容。这与日记上下文不是一回事：日记仍必须先走 `request_diary_context` 并经用户确认。

## 不要做

- 不要因为切页、杀进程或重新打开应用就清空当前对话。
- 不要把以前作废的「八个功能侧边栏 / 独立横屏」解禁。
- 不改四档文字状态、确认卡主路径和 Emotion Ball 官方 ID 规则（语音触发的 `35` 已随语音取消）。
- 本包不要改球布局、陀螺仪或月份同步。
