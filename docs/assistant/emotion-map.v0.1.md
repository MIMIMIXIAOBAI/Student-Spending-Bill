# 情绪与状态映射 v0.1

文字状态仍是主体，取值只能是：思考、调用工具、等待确认、出错。Emotion Ball（WebView，上游 `sam70361/aora-bot` 的 emotion-ball 造型）在 **AI 页主屏常驻**，用它替换原「AI消费建议」面板；**不再默认关闭，也不再用顶栏「球/关」开关**。记账首页先不放球。对话与球在同一 AI 页，不另放一颗小球。该造型不可商用，许可在关于页署名；Prompt 不重复展开法律文本。

球是视觉陪伴，不能替代四档文字状态、流式输出或确认卡。

## 占位（已冻，2026-11-10）

- 左右各留 16dp。
- 高度约为窗口的 40%，上限 320dp；对话区占剩余空间。
- 四档状态仍固定在输入栏上方；确认卡只出现在「等待确认」，并留在消息流里。
- 键盘弹出或出现确认卡时，球面板压缩到最低 160dp，不能挡住状态行和确认卡。

## 视线跟随

仍用 aora-bot `emotion-ball` 的 WebView，由应用计算坐标，不让模型输出视线字段。

- 页面上滑动或点击时，把触点相对球心归一化到 `[-1, 1]`，调用 `ball.setGaze(nx, ny)`。
- 松手后约 400ms 回到正视。
- 页面不可见或进入后台时调用 `setActive(false)` 停帧。

## 进行中状态（与界面文案一致）

| 协议状态 | 界面文案 | 球 | 说明 |
|---|---|---|---|
| thinking | 思考 | 轻微思考/专注，低动效 | 流式思考 |
| tool | 调用工具 | 短暂「工作」态 | 查询、运势、申请日记 |
| awaiting_confirm | 等待确认 | 等待/凝视，不欢快跳动 | 确认卡可见时；球面板压到不低于 160dp |
| error | 出错 | concerned，低动效 | 密钥失败、余额不足、网络错误；说明原因后停在这一档，不加新页面 |

## 结果态（不要另做一套文案抢对话）

| 场景 | 建议情绪 | 不要做 |
|---|---|---|
| 查询成功并报出数字 | calm / 轻点头 | 大庆祝动画挡文字 |
| 查询为 0 | calm / 中性 | 沮丧或责备用户 |
| 记账确认并回读成功 | pleased，很快回到 idle | 长时间庆祝 |
| 用户取消确认 | idle | 表现失望 |
| 日记未授权 | idle，不追问第二次以上 | 假装已读日记 |
| 运势 | light / 轻松 | 改成占卜独立页 |
| 工具失败、密钥失败、余额不足、网络错误 | 文字状态为「出错」；球可选 concerned | 假装成功、另开错误页 |

## 映射来源（应用计算，不让模型乱设情绪）

优先由客户端根据状态机映射，模型不必输出情绪字段。若以后要加可选字段，仅允许：

`idle | thinking | tool | awaiting_confirm | error | pleased | calm | concerned | light`

禁止新增恐怖、卖萌过度、持续闪烁等干扰评审阅读的状态。
