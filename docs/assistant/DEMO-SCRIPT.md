## 0. 三条硬规矩

1. **不伪造成功**：没有 Key、没有网络时，不录 App 内 AI 成功；确认卡没点“确认”之前，不剪出“已写入”的画面。
2. **数字只从屏幕来**：脚本里的 `¥210.00`、`¥228.00`、`¥1272.00` 等来自 §1.4 的预置数据。录制时如果屏幕不是这个数，按屏幕念，并在 §7 实测表里记下差异。
3. **Key 不出现**：演示机预置已测通的 DeepSeek Key；全片不展示 Key 输入、剪贴板或 Keystore。若必须拍向导，整段打码，只保留“测通了”的结果。

### 链 1｜账单查询：金额只能来自本轮 `query_spend`

**目标**
用户问“这周食堂花了多少”“我一共花了多少”“我有什么消费习惯”时，金额、笔数、分类、商户只能来自本轮对本机 Room 的只读查询；范围包含历史导入和手动记账；未指定时间或问历史/习惯/建议时用 `period=all`；应用侧在查账成功前不放出带数字的回复。

**原始 Prompt（归档原文）**
- `docs/assistant/process/DECISION_LOG.md:895`（用户，2026-11-11 01:21）：
  > 用户发送问题时，若对话内容涉及账单数据，需要先检查用户历史导入的账单数据再回复；回复内容需要有历史账单的真实数据支撑。用户认为现在的回复逻辑似乎没有检查用户的历史账单。
- 同日 `DECISION_LOG.md:903` 再次记录同一意见。
- 主管冻结见 `DECISION_LOG.md:912` 与 `:921`：
  > 涉及账单或消费的问题，必须先查本机 Room 里的真实账单再回答。金额、笔数、商户和分类只能来自本轮 `query_spend` 的结果，不能口算或编。……没指定、或问历史/整体习惯/消费建议时，用新的 `period=all` 查全部记录……应用侧也要卡住：这类问题若本轮还没成功查到账，就不要把带数字的回复直接给用户。

**AI 修改建议**

**实际修复与验证**

## 6. 降级预案

### 6.1 无 Key / 无网络

- **不能做的事**：录 App 内“联网 AI 成功”的画面；用旧片或别的构建冒充。
- **替换方案**：
  1. S3、S4 的离线芯片照常录（不依赖 Key/网络），保留飞行模式证据。
  2. S5 改为**开发侧 Prompt 链录屏**：打开 `docs/assistant/SYSTEM_PROMPT.v0.1.md:17-21`、`intent-control.v0.1.md:5-11`、`AssistantController.java:132/262-265`，讲“先查再答”和 `ReplyGate`。
  3. S6 改为终端实跑 `.\gradlew.bat testDebugUnitTest --tests "...AssistantCoreTest"`，展示 `demo_确认前不写库确认后回读一致` 等测试通过。
  4. S7 保留过程页与“无 Key 出错”B-roll；在画面角标注明 **“降级：无 Key，联网段未录”**。
  5. 口播明说“这一段没有演示 App 内 AI 成功，原因是演示机没有可用 Key/网络”，不得含糊。
- **时长**：降级后仍按 7 段剪，S5/S6 用开发录屏填充；若总时长不足 5 分钟，补 S4 的明细核对镜头，不要靠慢放凑。

### 6.2 无 adb 设备

- S2 的安装段替换为：已录好的 `BUILD SUCCESSFUL` + `adb devices` 空列表 + 字幕 **“无真机，安装步骤未实拍；以下 App 画面为同一构建的录屏”**。
- App 操作段用同一构建的录屏；不得用不同版本画面混剪。
- S1 的 `installDebug` 命令保留在字幕里，口播说明“有设备时执行这条”。
- 只有一台设备时，先拍干净安装段（S2：0 笔、预算 1500），再导入 §1.4 的 4 笔预置数据拍 S3–S7，两段以字幕标注「同机两段、非同一画面」，不得用同一画面冒充两个状态。

### 6.3 首页预算卡片仍误报“超出”

- 该问题已由四态预算修复（`1ec1f3c`：`hasBudget` 优先、未设预算走中性态、真实超支仍显示红色“超出”）修复；旧实现先判 `emptyState`，已设预算也会显示“请先导入账单”。
- 若片中出现“超出”，先核对设备装的是不是含 `1ec1f3c` 的包；S3/S4 的总支出芯片不依赖预算卡片，可先录。

### 6.4 模型等待过久 / 网络抖动

- 只允许加速等待段（画面角标“等待已加速”），不得跳过“思考 → 调用工具 → 等待确认”的状态变化。
- 若真实失败，保留“出错 + 重试”并重试一次；不要剪成一次成功。
